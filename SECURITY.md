# Безопасность «Соседей»

Проверка приложения: 3 ноября 2026. Изменения относятся к коду приложения и зависимостям; настройки CI, хостинга, DNS и секреты не изменялись.

## Границы доверия

- Просмотр анкет и комнат требует подписи Telegram. Изменения, приглашения, голоса и внутренние заявки дополнительно проверяют привязку аккаунта к своей анкете. Имя пользователя, ID из браузера и параметры запроса не подтверждают владение.
- Сервер проверяет две разные HMAC-схемы Telegram, срок входа (по умолчанию 24 часа), допустимое время в будущем и структуру пользователя. Администраторы определяются существующим серверным списком Telegram ID и той же проверенной подписью. Служебные вызовы бота требуют отдельного секрета. Личные уведомления привязываются только к личному чату пользователя; команды в группе не запрашивают и не публикуют личные заявки. Отсутствующий токен не открывает API или админку.
- Локальный обход авторизации требует одновременно `APP_ENV=development`, `ALLOW_INSECURE_DEV_AUTH=1` и отсутствия токена. Он предназначен только для синтетических данных. Администраторских прав он не даёт.
- Новая анкета связывается с подписанным Telegram ID. Контактный ник берётся только из той же подписи и обновляется при входе; аккаунт без публичного ника может сохранить анкету с пустым контактом, но не подтвердить чужой ник. Одновременное создание с одним ID сериализуется транзакционной блокировкой PostgreSQL. Старые записи не удаляются и не перепривязываются по изменяемым никам. Восстановление непривязанной старой анкеты требует отдельной проверки администратором.

## Данные и файлы

Текстовые поля ограничены на сервере; React выводит их как текст. Контактные ссылки и URL старых фотографий проверяются перед отображением. Фотографии принимаются от вошедших пользователей с ограничениями размера запроса, файла и числа пикселей; результат заново кодируется в JPEG без исходных метаданных. При получении аватара сервер разрешает только HTTPS-адреса Telegram CDN, проверяет каждый редирект и ограничивает загружаемые байты. CSV и Excel сохраняют пользовательские значения как текст, а не формулы. Ошибки Telegram и журналы не содержат токенов или содержимого сообщений.

Ответы приватного API имеют `Cache-Control: no-store`, `nosniff` и политику referrer. Frontend nginx задаёт CSP: внешние скрипты ограничены Telegram, объекты запрещены, базовый URL ограничен своим origin. Встраивание разрешено Telegram Web и своему сайту. Inline-стили нужны SDK Telegram; inline-скрипты не разрешены, ранняя установка темы вынесена в локальный файл. HTTPS, blob и data изображения оставлены для старых фото, предварительного просмотра и встроенных стрелок select.

## Проверка и ограничения

Регрессии используют только синтетические подписи, изолированную SQLite и временные файлы: чужие/новые пользователи, отсутствие конфигурации, устаревшая/поддельная подпись, создание и редактирование своей анкеты, сервисные вызовы бота, пределы загрузки, опасные URL и экспорт. Браузерная проверка использует собранный frontend с CSP и SDK-заглушкой, подписанной отдельным тестовым ключом. Внешние Telegram-запросы на стенде отключены. Frontend Docker build и `nginx -t` проверяются отдельно.

`npm audit` и `pip-audit` проверены для разрешённых зависимостей frontend, backend и бота; известных предупреждений на дату проверки не осталось. Это снимок реестров, а не гарантия отсутствия неизвестных уязвимостей.

Подпись остаётся повторно используемым bearer-доказательством в пределах срока жизни; одноразовые серверные сессии и принудительный отзыв не добавлены. Загруженные JPEG имеют публичные случайные адреса и не считаются закрытым хранилищем. Старые внешние HTTPS-фото могут обращаться к стороннему серверу (без referrer). Общие квоты, сетевые rate limits, резервное копирование и конфигурация рабочего окружения требуют отдельного эксплуатационного контроля. Реальная Telegram-авторизация, реальная база и рабочие секреты в этой проверке не использовались.

Официальные схемы: [Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [legacy Login Widget](https://core.telegram.org/widgets/login-legacy#checking-authorization).
